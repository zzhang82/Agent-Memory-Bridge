# v0.25.2 - Evidence Integrity

Agent Memory Bridge 0.25.2 makes retrieval feedback auditable against the
exact evidence an agent saw. It retains the 13 public MCP tools while expanding
the `recall` and `feedback` argument schemas.

## What changed

- Receipt-bearing memory recall now reads result rows, database epoch, and
  receipt evidence from one SQLite snapshot.
- The signed receipt carries the complete exposure set, exact content versions,
  and a canonical retrieval-contract digest.
- Callers may add model, harness, and chat-template context, but AMB stores only
  their digests and labels them `caller_declared_not_authenticated`.
- Feedback is an append-only event chain with `vote`, `correction`, and
  `retraction`.
- Each receipt/result subject has one current effective vote. Changing
  caller-declared client or session labels does not create additional voting
  power.
- Stale idempotent retries return the event's current effectiveness rather than
  pretending an old superseded vote is still active.
- Schema v7 keeps the actual receipt token hash in `receipt_hash` and stores the
  stable vote subject separately as `feedback_identity_digest`.
- Existing v5 and v6 databases migrate transactionally; injected v7 failure
  coverage verifies rollback of DDL, data, ledger, and user version.

## Boundaries

This release does not activate feedback-based reranking, automatic promotion,
policy mutation, authenticated identity, ACLs, ANN retrieval, graph memory, an
episode ledger, branch comparison, or training export.

Receipt tokens are signed, not encrypted. Semantic capability remains
configuration-declared rather than runtime-verified. Feedback remains
shadow-only and does not change memory records, indexes, recall ordering, or
ranking.
