# v0.27.0 - Closed-Loop Episode Ledger

Current source release: `0.27.0`

Current source test collection: `743 tests`

This document records the release-facing source surface. It does not assert a
Git tag, remote publication, visible GitHub Actions green run, host-product
certification, or a productivity result.

## What changed

- Schema v8 adds append-only `agent_runs`, `run_work_items`, `run_events`,
  `run_artifacts`, `run_outcomes`, and `run_memory_links` authority. Current
  run/work-item state and `memory_utility_shadow` are rebuildable projections.
  Run, event, outcome, artifact, and link rows are durable episode authority;
  projections and downstream learning/consolidation effects are shadow-only.
- Four additive MCP tools make run state explicit and stateless:
  `begin_run`, `record_run_event`, `get_run`, and `complete_run`.
- The canonical public surface is exactly 17 tools in
  `mcp_boundary.PUBLIC_TOOL_ORDER`; its frozen schema digest is
  `6349ee0220a30ed910846766e927a8e057a9e3fbcdbaa4e3857a2ca740f93577`.
- Run events record bounded structured summaries, evidence references, and
  declared provenance. They recursively reject raw-transcript, hidden-reasoning,
  and normalized analysis/thought-process field names. `artifact_created` writes
  a server-minted artifact ID linked to caller-declared, validated digest, MIME,
  URI, and reference metadata; metadata rejects inline-body keys `body`,
  `file_body`, and `fileBody` recursively.
- `memory_recalled`, `memory_applied`, and `memory_rejected` use receipt-bound
  attribution where available. The database stores only validated receipt hashes,
  exact content versions, and ranks. AMB rejects receipt-shaped values before
  durable SQLite persistence and does not echo them in validation errors.
  External client and process logging are outside this guarantee.
- `complete_run` records append-only outcomes. Verified success requires
  deterministic-verifier or human evidence; agent self-report alone remains
  unverified. The first outcome requires every explicit root/child work item to
  have an existing terminal ledger event; later outcome corrections still append
  by superseding the current head.
- `agent-memory-bridge consolidate-runs --shadow` reads completed runs and
  emits deterministic review evidence. It does not write ordinary memory,
  ranking, policies, prompts, or files. `--stage` may only create hidden
  review candidates.

## Compatibility evidence

The existing dual-era stdio contract is retained: modern `server/discover` is
`300000/public`, while legacy `initialize` and modern `tools/list` remain
compatible with their established result/cache shapes. An independent local
Linux/Python 3.12 project-interoperability run exercised AMB 0.27.0 on
`mcp==2.0.0`: a separate `mcp==1.28.1` legacy client listed the exact canonical
17 tools and completed `store`, `recall`, `begin_run`, `record_run_event`,
`get_run`, and `complete_run`; the modern MCP/raw-wire/operator target passed 32 pytest items,
including receipt attribution and atomic invalid-receipt rejection; and the
official `@modelcontextprotocol/client@2.0.0` completed the modern exact-17-tool,
cache, and episode flow. A separate reliability proof retained 20 writes across
20 writers and completed 100 connect/disconnect cycles without reported errors,
remaining direct child processes, or temporary artifacts.

This is local Linux/Python 3.12 project-interoperability evidence only, not a
GitHub CI result, official conformance, host certification, Windows proof, tag,
publication, or productivity result.

## Deliberate boundaries

- No MCP Tasks, hosted execution, HTTP transport, OAuth, or access-control
  system is added.
- No automatic reranking, automatic prompt/policy modification, automatic
  lesson promotion, or online training is enabled.
- Durable episode rows and `memory_utility_shadow` do not change normal recall
  ordering. Only projections and downstream learning/consolidation effects are
  shadow-only.
- The companion AMH event-trigger suite is a reviewed deterministic reference
  replay with `real_runtime_evidence=false`; it is not a runtime completion,
  failure-loop, or recall-frequency result.

The normal release-commit CI evidence remains required after an approved commit
and push; this document does not assert that evidence exists.
