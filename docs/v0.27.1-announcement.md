# v0.27.1 - Episode Authority & Recovery Integrity

Current source release: `0.27.1`

Current source test collection: `767 tests`

This is the local release-facing source surface. It does not assert a Git tag,
remote publication, GitHub Actions completion, host certification, verified
learning, or a productivity result.

## What changed

- Schema v9 adds `terminal_at` and `current_outcome_updated_at` to the run-state
  projection through an authority-preserving v8-to-v9 migration. Existing run,
  event, outcome, artifact, and link rows remain durable episode authority;
  projections and downstream learning/consolidation effects are shadow-only.
- Work-item transitions use an explicit FSM. For version-1 compatibility,
  `work_item_started` can resume a blocked item, but terminal reopen attempts
  fail atomically. New child work items require an active parent.
- `record_run_event` accepts optional `expected_last_sequence` and
  `expected_work_item_status` compare-and-swap preconditions. When callers
  supply them, stale state assumptions are rejected before a durable append.
- `get_run` reads one SQLite transaction, derives authority state, and returns
  `snapshot_epoch`, `snapshot_last_sequence`, `projection_health`, and
  `degraded`. Mutating run writes fail closed while a run projection is drifted;
  repair can restore the derived view without rewriting episode authority.
- Outcome correction keeps the original `terminal_at` and tracks the current
  outcome head separately with `current_outcome_updated_at`.
- The public completion path accepts `regression_of_run_id` only for a
  `regression` outcome. The legacy schema-v9 table keeps its one-way database
  check; DB-level inverse enforcement is deferred to schema v10 in 0.27.2.
- The canonical public tool names and order remain exactly 17. The
  `record_run_event` input schema gains the two optional CAS fields, and the
  resulting schema digest is
  `a2e3dbbb48c87a7ce23bc4be1c8ea37c8cd176ff8f7fd2318d1374bc9e089e4a`.

## Authority boundary

Run, event, outcome, artifact, and link rows are the durable episode authority.
`get_run` derives recovery state from those rows; it does not treat a stale
projection as authority. Event ingestion still rejects raw transcript and
hidden-reasoning fields, and rejects receipt-shaped values before durable
SQLite persistence. Artifact metadata rejects inline-body keys including
`body`, `file_body`, and `fileBody` recursively.

Existing v1 `verified_success` outcomes remain readable and are classified as
`legacy_declared`. They are not strong verification and cannot authorize a
regression target, consolidation support, or utility supporting-run credit.
Governed-v2 verification receipts are deferred to 0.27.2.

## Consolidation and utility

`agent-memory-bridge consolidate-runs --shadow` remains read-only by default.
`--stage` can only create hidden `needs_review` candidates; it cannot promote a
lesson or change ordinary recall. Utility and consolidation remain shadow-only.
The current source does not claim evaluated episodes, comparative learning,
automatic reranking, automatic policy changes, or durable writeback from raw
transcripts.

## Compatibility and install boundary

The 17 public tool names and order, plus the dual-era local stdio contract, remain
unchanged; the additive `record_run_event` input fields change the tool-schema
digest.

Use the pinned `v0.27.1` source route only after its exact-commit CI gate has
passed and the tag exists; before then, use a source checkout:

```text
<venv-python> -m pip install "https://github.com/zzhang82/Agent-Memory-Bridge/archive/refs/tags/v0.27.1.zip"
<venv-python> -m agent_mem_bridge doctor
<venv-python> -m agent_mem_bridge verify
```

The current source does not claim that a client vendor certified AMB, that a
host loaded its configuration, or that local interoperability evidence is full
CI or official conformance evidence. Client registration remains a separate
local check through the client's MCP status/tool view.
