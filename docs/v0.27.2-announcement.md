# v0.27.2 - Governed-v2 & Watcher Continuity

This feature set is included in the local `0.27.3` source candidate. It is
unpublished: this note does not assert a standalone `v0.27.2` tag, push,
publication, remote CI result, host certification, or productivity result.

## What changed

- Governed-v2 run profiles require bounded acceptance criteria and closed typed
  preflight/evidence events. Event writes support transactional sequence,
  status, database-epoch, and run-generation compare-and-swap preconditions.
- A bounded operator CLI mints server-linked verification receipts. A strong
  `verified_success` must match the governed-v2 profile, approved preflight,
  acceptance criteria, current artifacts, run configuration, evaluator, and
  database epoch. Legacy v1 `verified_success` remains readable as
  `legacy_declared`, but is not strong verification.
- Watcher scans read only complete JSONL bytes appended after a validated
  cursor. Cursor state keeps bounded file identity, offsets, counts, and
  digests; message bodies are not persisted in watcher state.
- Idle watcher rollouts pause instead of being treated as terminal. Completion
  requires explicit close from the host. If a terminal rollout grows later,
  the watcher starts an explicit continuation run linked to the prior run.
- The modern and legacy stdio paths retain the same deterministic 17 public MCP tools;
  watcher and operator receipt helpers remain outside the MCP tool
  surface.

## Authority boundary

Run, event, outcome, artifact, and link rows remain durable episode authority;
projections and downstream learning/consolidation effects are shadow-only.
Receipts are evidence for governed completion, not authenticated caller
identity. Declared provenance labels do not grant authority. No feature here
changes recall ranking, policy, prompts, ordinary memory, or automatic
writeback.
