# Agent Memory Bridge v0.32.0 — Project Learning UX

Agent Memory Bridge can now turn a repository and explicit project decisions
into one inspectable project view.

**Code tells AMB what the project is.**

**Conversations teach AMB why it is that way.**

AMB gives connected coding-agent workflows shared, inspectable project context
across sessions without treating repository facts and human decisions as the
same authority.

This document is the canonical release-notes artifact for the `0.32.0`
source/package line. Published release availability and pinned archives are
determined by the live
[GitHub Releases](https://github.com/zzhang82/Agent-Memory-Bridge/releases)
page. There is no `pip install agent-memory-bridge==0.32.0` route.

## The shortest Project Learning journey

1. Connect AMB to a coding client.
2. Run `project init .`.
3. Confirm the suggested project namespace.
4. See **CODE / WHAT** immediately in Human-first Explore.
5. Tell the connected coding agent one decision naturally, including its reason.
6. Start a fresh session using the same AMB home.
7. Explore shows repository WHAT together with governed project WHY.
8. Inspect explains why relevant context surfaced for a question.

The primary journey is human-readable. It does not require users to read raw MCP
JSON or author internal record schemas.

## Human-first Project Knowledge

Default Explore now presents:

- **PROJECT**
- **CODE / WHAT**
- **CONVERSATION / WHY**
- **STATUS**

Active decisions and constraints show their recorded reasons. Humanized
supersession and compact active counts keep the first screen readable. Raw graph
relations remain available in technical Markdown, while
`knowledge-explorer-v1` remains the deterministic machine contract.

## Project Init

`project init [path]` detects a local Git repository, proposes a project
namespace, and requires explicit confirmation before mutation. After
confirmation it freshly revalidates repository identity, checkout eligibility,
and bindings, then reuses the existing derived repository WHAT bootstrap and
renders Human-first Explore.

The command supports an explicit namespace override, `--yes`, and zero-write
`--dry-run`. Dirty repositories, identity changes, and namespace conflicts fail
closed. Binding is never silently changed.

On first success it reports that repository WHAT was initialized. On repeat for
the same repository and namespace it reports:

> Repository WHAT refreshed; existing project WHY is unchanged.

Repeat init does not duplicate durable memory or rewrite decisions and
constraints.

## Authority and safety

- Repository WHAT remains `derived_repository`: bounded, commit-aware,
  rebuildable, and withheld when current repository truth cannot be proven.
- Project WHY remains `governed_durable_memory`: explicit decisions and
  constraints stored through existing public memory contracts.
- Project Init writes no WHY and creates no repository-fact memory rows.
- There is no automatic learning, automatic WHY inference, automatic durable
  writeback, silent rebind, or new authority lane.

## Explicit non-goals

This release does not add automatic learning, automatic durable writeback,
Controlled Adaptation, a graph database, a dashboard, an IDE sidebar, a schema
migration, network repository discovery, new ranking or retrieval semantics,
non-Python runtime inference for presentation, or a new Explorer JSON schema.
