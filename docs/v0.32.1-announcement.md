# Agent Memory Bridge v0.32.1 — PyPI Distribution

Agent Memory Bridge v0.32.1 makes PyPI the normal release install route while preserving the Project Learning behavior and authority boundaries introduced in v0.32.0.

```bash
pip install agent-memory-bridge==0.32.1
```

This document is the canonical release-notes artifact for the `0.32.1` source/package line. Live publication state is external: use GitHub Releases for the source release and PyPI for package availability.

## Distribution

The repository now includes a release-triggered Python publishing workflow. When a GitHub Release is published, the workflow:

1. checks out the release tag,
2. requires the tag to equal `v<project.version>`,
3. builds the wheel and source distribution,
4. runs `twine check`, and
5. publishes through PyPI Trusted Publishing using GitHub OIDC.

The publish job is bound to the GitHub `pypi` environment and receives `id-token: write`. The repository does not require a PyPI API token for this path.

Publishing is not triggered by merging this source line. It is triggered by publishing the matching GitHub Release after the Trusted Publisher is configured.

## Install paths

For the release package:

```bash
python -m venv .amb-venv
<venv-python> -m pip install agent-memory-bridge==0.32.1
```

For development or audit work against an exact checkout:

```bash
<venv-python> -m pip install -e .
```

GitHub Releases remains the authority for tagged source releases and release notes.

## Product behavior is unchanged

v0.32.1 is a distribution and onboarding patch. It does not add a new memory lane, authority lane, retrieval mode, automatic learning path, or MCP tool.

The Project Learning model remains:

**Code tells AMB what the project is.**

**Conversations teach AMB why it is that way.**

Repository CODE / WHAT remains derived and rebuildable. Explicit project WHY remains governed durable memory. `project init` remains the preferred first-project path, and Human-first Explore continues to keep WHAT and WHY visibly separate.
