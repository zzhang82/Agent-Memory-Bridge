# Agent Memory Bridge v0.32.2 — Governed Project Memory

Agent Memory Bridge v0.32.2 is a product-positioning and onboarding release. It does not add a new memory authority or expand the MCP tool surface. Instead, it makes the existing product easier to understand and easier to connect correctly across coding agents.

## Turn scattered project context into governed memory

The README now leads with the broader product story:

> **Turn scattered project context into governed memory.**

AMB is framed as project memory rather than only codebase memory. Repository state remains a common software-project baseline, while durable decisions, constraints, corrections, provenance, and other reviewed context can continue across sessions and tools.

The new hero visual follows the same story: fragmented sessions and tools feed a governed AMB memory core, and future sessions can reuse the resulting project context.

The English and Simplified Chinese READMEs use the same positioning.

## Installation and client registration are separate

Installing the package does not automatically connect every coding agent on the machine.

The Quick Start now makes the intended flow explicit:

1. install AMB into one stable virtual environment;
2. preview configuration for each coding client with `setup --client <client>`;
3. explicitly use `--apply` only when AMB marks that client configuration as safe to write;
4. follow the client-specific integration path when automatic configuration is intentionally unavailable;
5. point clients that should share memory at the same persistent `AGENT_MEMORY_BRIDGE_HOME`;
6. initialize the project and start teaching reviewed project knowledge.

`setup` remains read-only by default. This release does not turn package installation into silent client configuration.

## Install

PyPI Distribution remains the normal release route:

```bash
pip install agent-memory-bridge==0.32.2
```

Publication continues through PyPI Trusted Publishing with GitHub OIDC after a matching GitHub Release is published. No long-lived PyPI token is added.

## Compatibility and authority boundaries

This release intentionally keeps the implementation boundary stable:

- Durable schema remains v12; the release contract also records that the schema remains v12.
- Public MCP surface remains exactly 17 tools; the release contract therefore continues to require exactly 17 tools.
- The public tool-schema digest remains `24c5c52321d61b4b6f647c0d74e2d8304ca68716c403e08a274e9badfd8dc9f8`.
- Knowledge Explorer remains CLI-only with no MCP tool #18.
- Project Init does not create durable decisions and there is no automatic learning.
- Repository-derived knowledge remains rebuildable and separate from governed durable project knowledge.
- Revision, supersession, provenance, inspection, and local-first storage boundaries are unchanged.
- Runtime behavior, retrieval semantics, durable schema, and MCP wire contracts are unchanged from v0.32.1.
