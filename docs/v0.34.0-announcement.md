# Agent Memory Bridge v0.34.0: Remote Authority Deployment

Agent Memory Bridge v0.34.0 turns the remote-authority deployment work into a
published source release. It adds an optional standard MCP Streamable HTTP
deployment surface to the official package. One server/NAS owns the local
SQLite/WAL database. Remote clients call that authority; they never open its
database through NFS or SMB. The no-argument CLI and `serve --transport stdio`
preserve the local stdio path.

The same server and exactly 17 tools serve both transports. The schema remains v12
and the public tool-schema digest is unchanged. There is no automatic learning,
no MCP tool #18, and no PostgreSQL requirement.

Installing the package does not automatically connect every coding agent.
Local clients share the same persistent `AGENT_MEMORY_BRIDGE_HOME`; remote
clients connect to the same configured HTTP authority instead of mounting its home.

## Remote deployment

The container installs a wheel built from official source and runs as a
non-root user. Compose persists the bridge home separately from the container
and publishes only to host loopback by default. `/healthz` reports liveness;
`/readyz` reports bounded authority readiness without exposing memory content.

Remote exposure requires explicit host/origin configuration and an intentional
security boundary. The private bearer profile uses standard SDK authentication
primitives; it is not an OAuth authorization server or an assertion of full MCP
OAuth interoperability. Protect traffic with TLS or an authenticated tunnel.
Never forward a plaintext bearer endpoint onto an untrusted network.

Deployment startup checks the actual mounted filesystem. Known network storage
is rejected; unknown classification cannot pass hardened deployment. Ordinary
local operation retains compatibility and actionable diagnostics.

`doctor --url ... --json` and `verify --url ... --json` use read-only HTTP
readiness and MCP list/call probes. They do not open a fallback local database.
Migration uses consistent immutable snapshots and isolated copies, with explicit
epoch handling, durable-state comparison, and rollback rehearsal. Production
cutover remains a separate owner-approved operation.

## PyPI Distribution and container provenance

The version-pinned install command is:

```sh
pip install agent-memory-bridge==0.34.0
```

PyPI Trusted Publishing uses GitHub OIDC. GitHub Releases remains the source
release authority. PyPI and GHCR publication consume the same approved release
SHA; package version, tag, and image labels must agree. Live package and image
availability is external state. Upgrading an existing deployment remains a separate operator step.

## Evidence and limits

The frozen deployment scope and E1-E12 definitions are in
[the release contract](evidence/v0.34.0-remote-authority/CONTRACT.md). Missing
container, migration, cross-machine, or publication evidence is inconclusive,
not a unit-test-derived pass. Full OAuth integration, a stdio-to-HTTP shim,
container signing/SBOM, and multi-user authorization remain optional or deferred.
