# Agent Memory Bridge v0.34.1: Filesystem Portability Patch

Agent Memory Bridge v0.34.1 is a portability and reliability patch on the
v0.34 remote-authority line. It does not add a new deployment model, schema,
or tool. The schema remains v12 and the public MCP surface remains exactly 17 tools. There is no automatic learning and no MCP tool #18.

v0.34.0 classified the mounted filesystem before treating a path as a safe
SQLite/WAL authority. Two host gaps made that guard crash or mis-classify:

- Windows has no `os.major`/`os.minor`. Calling those helpers raised
  `AttributeError` instead of skipping POSIX device matching.
- Python 3.13 `Path.resolve(strict=False)` no longer raises on symlink loops.
  A loop could walk to a local ancestor and be classified `local`.

This patch keeps the fail-closed contract. Unsupported host semantics and
symlink-resolution loops return `unknown`. Known NFS, CIFS, SMB, and SSHFS
classifications stay `network` and remain rejected under strict local-FS
mode. Ordinary local operation is unchanged.

Installing the package does not automatically connect every coding agent.
Local clients share the same persistent `AGENT_MEMORY_BRIDGE_HOME`; remote
clients connect to the same configured HTTP authority instead of mounting its
home.

## PyPI Distribution and container provenance

The version-pinned install command is:

```sh
pip install agent-memory-bridge==0.34.1
```

PyPI Trusted Publishing uses GitHub OIDC. GitHub Releases remains the source
release authority. PyPI and GHCR publication consume the same approved release
SHA; package version, tag, and image labels must agree. Live package and image
availability is external state. Upgrading or patching an existing deployment remains a separate operator step.

## Evidence and limits

This patch does not widen filesystem allowlists, change the 17-tool contract,
or remediate historical invalid metadata. Missing publication evidence is
inconclusive, not a unit-test-derived pass.
