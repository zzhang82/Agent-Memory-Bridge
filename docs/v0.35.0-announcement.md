# Agent Memory Bridge v0.35.0 — Governed Lifecycle Activation

Agent Memory Bridge v0.35.0 brings governed project memory into optional host
lifecycle callbacks. Hooks can recall bounded, relevant history under the
confirmed project scope, while plain MCP remains usable without them. The
schema remains v12 and the public MCP surface remains exactly 17 tools.
There is no automatic learning, no automatic durable promotion and no MCP tool #18.

## Scope, recall and candidate capture

- `project resolve` reads the existing governed project/worktree binding. Hooks
  do not invent a namespace, bind a checkout or make injected context authoritative.
- Optional lifecycle activation recalls material history, skips deterministic
  work, distinguishes successful empty recall from unavailable authority and
  reconciles stale guidance against inspected repository evidence. Nonstale
  historical facts can be attributed to AMB without claiming independently
  verified current runtime state. Exact repeated prompts are suppressed;
  reworded prompts may recall again. Compaction continuity is a derived view.
- A configured remote lifecycle authority is exclusive: recall uses HTTP and
  never silently falls back to local SQLite. Transport/backend failure is
  `error`, not successful `no_hit`.
- Codex Stop can capture one already structured visible artifact as a hidden
  local `needs_review` candidate. It does not summarize a conversation, read a
  transcript, persist hidden reasoning or promote the candidate automatically.
  Remote capture is blocked rather than falling back to a local writer.

Installing the package does not automatically connect every coding agent.
Local clients share the same persistent `AGENT_MEMORY_BRIDGE_HOME`; remote
clients use the same configured HTTP authority. Optional hook loading is a
separate host configuration step; plain MCP does not require lifecycle hooks.

## Matched native evidence

The frozen ten-case v2 benchmark retains its historical **3 PASS / 7 FAIL**
baseline, the isolation-rejected pilot and the valid intermediate **8/10** run.
The repaired source completed **10 PASS / 0 FAIL / 0 INCONCLUSIVE** under the
matched reference condition:

```text
Codex CLI        0.160.0
Model            gpt-6-luna
Condition        adapter_enabled
Backend          remote_loopback
Hook loading     invocation_inline
Benchmark        frozen v2, same ten cases and expected decisions
Measurement      codex-repo-read-v1
Grader           unchanged
Timeout          150 seconds native, 210 seconds outer; parallelism 2
Isolation        same required contract
```

Actual callbacks prove no-hit and unavailable discrimination. Required recall
is 5/5, false activation 0/2, no-hit 1/1, unavailable discrimination 1/1,
stale misuse 0 and unnecessary recall 0. All cases completed normally with
fixture isolation and unchanged durable-memory rows. Canonical post-merge
source/report/receipt verification reproduced the checked-in report without
new model calls. See the [matched evidence](evidence/issue-51-codex-matched/README.md)
and [frozen release contract](evidence/v0.35.0-lifecycle/CONTRACT.md).

This supports bounded rule-based activation in the tested reference
configuration. It does not certify general natural-language history detection,
productivity gains, every model/host, native Windows activation, project/plugin
discovery or mixed/concurrent callback streams. OpenCode prompt activation
remains **NOT_RUN / pending** in its documented runnable lane. The frozen
repeated case verifies recall budget; exact-material-repeat and compaction
remain separate auxiliary evidence. Stop capture and the dedicated remote
authority trials retain their original source/configuration bindings.

## PyPI Distribution and release provenance

The version-pinned distribution command is:

```sh
pip install agent-memory-bridge==0.35.0
```

GitHub Releases is the source publication authority; consult it and PyPI for
live availability. PyPI Trusted Publishing uses GitHub OIDC. After the release
PR merges, tag `v0.35.0` must resolve to that release merge SHA. The existing
package and GHCR workflows verify tag/package/source identity and installed
wheel/sdist or container behavior before publication. Verify the published
container digest and its immutable revision label, then run a clean PyPI
install smoke. A tag alone is not publication evidence.

This release requires no schema migration or new public-tool integration.
Upgrading an existing deployment is a separate step for the operator.
