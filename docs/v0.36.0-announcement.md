# Agent Memory Bridge v0.36.0 — Core Boundary Cleanup

Agent Memory Bridge v0.36.0 installs and runs as a generic MCP memory service. Core no longer includes Codex, OpenCode, or any other named coding-client adapter. The schema remains v12 and the public MCP surface remains exactly 17 tools. There is no automatic learning and no MCP tool #18.

## Client boundary

`setup` and `config` are gone. `lifecycle-hook` still takes a host-neutral input, and it does not discover or certify a coding client. Clients that want stdio launch it themselves.

Installing the package does not automatically connect every coding agent. Clients that should share one store still point at the same persistent `AGENT_MEMORY_BRIDGE_HOME`.

The default home is `~/.local/share/agent-memory-bridge`, with configuration under `~/.config/agent-memory-bridge`. v0.36 does not open `~/.codex/mem-bridge` on its own. Set `AGENT_MEMORY_BRIDGE_HOME` to keep using that directory, or copy it to the neutral home. AMB does not migrate or delete it.

The public tool-schema digest is unchanged: `24c5c52321d61b4b6f647c0d74e2d8304ca68716c403e08a274e9badfd8dc9f8`. Tag `v0.35.0` still has the old per-client notes and the Codex Stop capture trial. Those files describe that tag, not this package.

## PyPI Distribution and release provenance

The version-pinned distribution command is:

```sh
pip install agent-memory-bridge==0.36.0
```

GitHub Releases is the source publication authority; consult it and PyPI for live availability. PyPI Trusted Publishing uses GitHub OIDC. After the release PR merges, tag `v0.36.0` must resolve to that release merge SHA. The package and GHCR workflows verify tag, package, and source identity, then check the installed wheel, sdist, or container before publication. A tag alone is not publication evidence.

This release requires no schema migration and adds no public tool. Upgrading an existing deployment is a separate step for the operator.
