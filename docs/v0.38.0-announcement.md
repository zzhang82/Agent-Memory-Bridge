# Agent Memory Bridge v0.38.0 — Optional HTTP gateway: per-client tokens, roles and audit logging

Agent Memory Bridge v0.38.0 adds an optional gateway in front of the Streamable HTTP transport. Each client can have its own token, a role decides which tools that token can call, namespace rules limit which memory it can touch, and every request to the MCP endpoint, including refused ones, writes one JSONL audit line. The schema remains v12 and the public MCP surface remains exactly 17 tools. There is no automatic learning and no MCP tool #18.

## What is in v0.38.0

This release adds:

1. **HTTP gateway and per-client tokens**:
   - Introduces `src/agent_mem_bridge/gateway/` as an ASGI middleware wrapping the existing Streamable HTTP transport.
   - Supports pre-hashed SHA-256 tokens (`sha256:<digest>`) or explicit private tokens loaded via `amb_tokens.json`, `AMB_GATEWAY_CONFIG_FILE`, or `AMB_GATEWAY_CONFIG`.
   - In-memory rate limiting per principal (configurable requests per minute).
   - Local `stdio` is unchanged. It does not go through the gateway and needs no token configuration, and existing stdio host configurations need no changes.

2. **Roles and namespace limits**:
   - Enforces four distinct operational roles:
     - `admin`: full access across all 17 MCP tools and all namespaces.
     - `writer`: durable memory creation, recall, browse, annotation, revision, feedback, and run event logging; blocked from deletions, promotions, and exports.
     - `reader`: read-only inspection (`recall`, `browse`, `stats`, `get_run`); strictly blocked from all mutating tools.
     - `orchestrator`: dedicated run lifecycle and signal coordination (`begin_run`, `record_run_event`, `complete_run`, `get_run`, `claim_signal`, `extend_signal_lease`, `ack_signal`, `recall`, `browse`).
   - Wildcard and literal namespace pattern matching (`project:*`, `domain:*`, `*`, exact match) blocks cross-namespace memory access.
   - Actor binding: in gateway RBAC mode, the `actor` on `store`, `annotate`, `revise` and `feedback` is set to the caller's verified `principal_id`, whatever name the caller sends. A caller can't write under another principal's name. It identifies the configured principal, not the person or model behind it.

3. **Structured audit logging (JSONL)**:
   - Emits structured, single-line JSONL audit events for every interaction (success, 401 unauthenticated, 403 forbidden, 429 rate limited, error).
   - Writes to stdout, stderr, or a dedicated log file, kept separate from the SQLite database so audit writes don't compete for database locks.
   - Captures request ID, principal ID, client IP, tool, namespace, execution duration in milliseconds, arguments summary, and output summary.

## Client boundary

Installing the package does not automatically connect every coding agent. Clients that should share one store still point at the same persistent `AGENT_MEMORY_BRIDGE_HOME`. In HTTP deployments, clients authenticate via standard `Authorization: Bearer <token>` headers.

## Public tool and schema invariants

The public tool-schema digest is unchanged: `24c5c52321d61b4b6f647c0d74e2d8304ca68716c403e08a274e9badfd8dc9f8`.

- The public tool surface stays frozen at **exactly 17 tools**.
- The durable database schema stays on **v12**.
- No schema migration is required. Existing v12 databases are used as they are.

## PyPI Distribution and release provenance

The version-pinned distribution command is:

```sh
pip install agent-memory-bridge==0.38.0
```

GitHub Releases is the source publication authority; consult it and PyPI for live availability. PyPI Trusted Publishing uses GitHub OIDC. After the release PR merges, tag `v0.38.0` must resolve to that release merge SHA. The package and GHCR workflows verify tag, package, and source identity, then check the installed wheel, sdist, or container before publication. A tag alone is not publication evidence.

This release requires no schema migration and adds no public tool. Upgrading an existing deployment is a separate step for the operator.
