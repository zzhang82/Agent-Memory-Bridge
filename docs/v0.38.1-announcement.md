# Agent Memory Bridge v0.38.1 — Documentation Accuracy and Evidence Hygiene

Agent Memory Bridge v0.38.1 packages the documentation and release-wording cleanup merged in [PR #82](https://github.com/zzhang82/Agent-Memory-Bridge/pull/82). This is a documentation and release-metadata maintenance update over v0.38.0, not a new gateway implementation. The schema remains v12 and the public MCP surface remains exactly 17 tools. There is no automatic learning and no MCP tool #18.

## What changed since v0.38.0

- **Gateway descriptions:** The optional Streamable HTTP gateway is documented in terms of per-client Bearer authentication, four roles, namespace limits, and JSONL audit logging. Absolute sub-millisecond latency, zero-lock, and unconditional compatibility guarantees have been removed.
- **Identity and audit limits:** In RBAC gateway mode, `store`, `annotate`, and `revise` bind top-level `actor` to the configured principal; `feedback` binds `provenance.actor`. The configured principal does not prove the real human or model behind a request. Audit events cover requests that complete, are rejected, or raise a caught exception; disconnected requests are not universally guaranteed to produce a record.
- **Historical deployment evidence:** Old NAS-specific migration instructions were generalized. The v0.34 review ledger retains the historical `invalid_metadata_value_count=339` source-content validation failure and its non-acceptance, without implying that the current deployment has the same problem.
- **Frozen evaluation:** The original v0.34 E9 migration acceptance wording remains unchanged from the `v0.34.0` release tag. Historical release bodies and old tags were not rewritten.
- **Scope:** No new gateway, memory, or MCP runtime functionality was added in PR #82. The migration rehearsal script's human-readable result text was clarified; release metadata and installation examples now identify v0.38.1.

## Compatibility and limitations

- The public tool-schema SHA-256 remains `24c5c52321d61b4b6f647c0d74e2d8304ca68716c403e08a274e9badfd8dc9f8`.
- There are exactly 17 tools in the public MCP interface, and the schema remains v12.
- No schema migration is required for existing v12 data. The default local stdio path and the optional remote HTTP authority keep their existing implementation boundaries.
- This release does not authorize upgrading an existing production deployment or moving its authority; those operations require an independent operator decision.

## PyPI Distribution and release provenance

After this release is published, install the version-pinned package with:

```sh
pip install agent-memory-bridge==0.38.1
```

GitHub Releases remains the release source of truth, and actual PyPI and GHCR availability must be checked separately. After the release PR is reviewed and merged, the `v0.38.1` tag must resolve to that exact release merge SHA. Publishing a GitHub Release for the tag triggers the existing wheel/sdist build and verification workflow, followed by PyPI Trusted Publishing through GitHub OIDC, and a separate container workflow that validates and publishes `ghcr.io/zzhang82/agent-memory-bridge:0.38.1`. A tag alone is not evidence that either artifact was published.

Release validation includes the existing CI, installed wheel and sdist stdio acceptance checks, container provenance and persistence checks, and the release/public-surface/onboarding contract gates.
