# Agent Memory Bridge v0.38.4 — Gateway Memory Ownership

Agent Memory Bridge v0.38.4 limits cross-principal memory edits in the optional HTTP gateway. A non-admin principal may annotate or revise only a memory whose stored actor matches that principal. The schema remains v12 and the public MCP surface remains exactly 17 tools. There is no automatic learning and no MCP tool #18.

## What changed since v0.38.3

- **Gateway ownership:** In gateway RBAC mode, `annotate` and `revise` compare the memory's stored actor with the caller's verified principal ID. A non-admin is refused when they differ.
- **Admin corrections:** An admin may still annotate or revise another principal's memory. The gateway records the caller's principal ID as the new actor.
- **Empty actor:** A memory with no stored actor is not treated as owned by the caller. A non-admin annotate or revise is refused.
- **Unchanged paths:** `store` remains limited by role, namespace, and any configured `allowed_record_types`. Local stdio and the static single-token profile do not apply this ownership check.
- **Scope:** No schema migration, public tool argument, proposer role, or tool-schema digest change is included. The published `v0.38.3` tag and artifacts remain historical.

## Compatibility and limitations

Installing the package does not automatically connect every coding agent. Clients that should share one store still point at the same persistent `AGENT_MEMORY_BRIDGE_HOME`.

- The public tool-schema SHA-256 remains `24c5c52321d61b4b6f647c0d74e2d8304ca68716c403e08a274e9badfd8dc9f8`.
- There are exactly 17 tools in the public MCP interface, and the schema remains v12.
- No schema migration is required for existing v12 data.
- Existing memories stored before gateway actor binding may have an empty actor. A non-admin cannot annotate or revise those memories through the gateway; an admin can.
- The gateway does not add human approval, OAuth or token issuance, TLS termination, or human/model identity.
- This release does not authorize upgrading an existing production deployment. That remains an independent operator decision.

## PyPI Distribution and release provenance

After this release is published, install the version-pinned package with:

```sh
pip install agent-memory-bridge==0.38.4
```

GitHub Releases remains the release source of truth, and actual PyPI and GHCR availability must be checked separately. Publishing a GitHub Release for the `v0.38.4` tag triggers the existing wheel/sdist verification workflow, PyPI Trusted Publishing through GitHub OIDC, and the container workflow that validates and publishes `ghcr.io/zzhang82/agent-memory-bridge:0.38.4`. A tag alone is not evidence that either artifact was published.
