# Agent Memory Bridge v0.38.5 — First-Install Polish, Doctor Summary, and Record-Shape Guidance

Agent Memory Bridge v0.38.5 tightens POSIX directory permissions during `project init`, adds home/database/memory-count summary lines to `doctor`, aligns `first-run` and README examples with the `record_type: decision` / `record_type: constraint` shape used by `explore` and `inspect`, and adds Official MCP Registry `server.json` metadata. The schema remains v12 and the public MCP surface remains exactly 17 tools. There is no automatic learning and no MCP tool #18.

## What changed since v0.38.4

- **First-install directory permissions (#103):** `RepositorySnapshotStore` and `project init` ensure that the resolved bridge home, `repository`, and `snapshots` directories are created or tightened to `0700` on POSIX when persisting snapshots or bindings, so `doctor` reports `bridge_home_permissions: pass`. Read-only planning and `--dry-run` still create no files or directories.
- **Copy-paste install block (#103):** The English and Simplified Chinese READMEs use a runnable four-line install and check sequence (`python3 -m venv .amb-venv`, `.amb-venv/bin/python -m pip install agent-memory-bridge==0.38.5`, `project init . --yes`, `doctor`) and explain `<venv-python>`, `--yes`, and `--dry-run`.
- **Doctor summary (#102):** `doctor` includes `memories_stored` (active `kind="memory"` rows excluding hidden learning candidates and signals) and prints `home: ...`, `database: ...`, and `memories stored: ...` immediately below `overall: ...` in human output.
- **Record-shape guidance (#102):** `first-run` templates and the README store step show `record_type: decision` and `record_type: constraint` examples (`claim:` and `reason:`), clarifying that free-form `kind="memory"` notes still recall while `explore` and `inspect` list structured decision and constraint records.
- **Official MCP Registry metadata:** Adds root `server.json` (`io.github.zzhang82/agent-memory-bridge`) and the `<!-- mcp-name: io.github.zzhang82/agent-memory-bridge -->` ownership marker in `README.md` and `README.zh-CN.md`.
- **Scope:** No schema migration, public tool argument, or tool-schema digest change is included. The published `v0.38.4` tag and artifacts remain historical.

## Compatibility and limitations

Installing the package does not automatically connect every coding agent. Clients that should share one store still point at the same persistent `AGENT_MEMORY_BRIDGE_HOME`.

- The public tool-schema SHA-256 remains `24c5c52321d61b4b6f647c0d74e2d8304ca68716c403e08a274e9badfd8dc9f8`.
- There are exactly 17 tools in the public MCP interface, and the schema remains v12.
- No schema migration is required for existing v12 data.
- This release does not authorize upgrading an existing production deployment. That remains an independent operator decision.

## PyPI Distribution and release provenance

After this release is published, install the version-pinned package with:

```sh
pip install agent-memory-bridge==0.38.5
```

GitHub Releases remains the release source of truth, and actual PyPI and GHCR availability must be checked separately. Publishing a GitHub Release for the `v0.38.5` tag triggers the existing wheel/sdist verification workflow, PyPI Trusted Publishing through GitHub OIDC, and the container workflow that validates and publishes `ghcr.io/zzhang82/agent-memory-bridge:0.38.5`. A tag alone is not evidence that either artifact was published.
