# Agent Memory Bridge v0.38.6 — First-Run Bound Namespace Default, Lock File Permissions, and Documentation Polish

Agent Memory Bridge v0.38.6 makes `first-run` read the bound repository namespace by default, tightens the repository binding lock and binding files to `0600` on POSIX, and refreshes the public documentation for portability, remote two-harness use, and the comparison record. The schema remains v12 and the public MCP surface remains exactly 17 tools. There is no automatic learning and no MCP tool #18.

## What changed since v0.38.5

- **Bound namespace default (#107):** `first-run` without `--namespace` resolves the current checkout through `project resolve` and reads that bound project namespace. An unbound directory still falls back to `project:demo`, and an explicit `--namespace` always wins. The rendered report names the namespace it read and tells you how to pass `--namespace <namespace>` for another project.
- **Binding file permissions (#107):** `RepositorySnapshotStore` sets `bindings.lock` and the atomically written binding and snapshot JSON files to `0600` on POSIX, matching the existing `0700` directories.
- **Documentation (#92, #94, #98, #99, #100):** The bilingual READMEs link the companion-skill trigger moments and hook recipes and retitle the traceability section. Configuration documents how `backup`/`restore`, the `export` tool, and `scripts/import_profile_memory.py` differ. Remote deployment documents two machines and two harnesses sharing one HTTP authority through one explicit project namespace. The comparison record adds basic-memory, Letta Code, and the Cursor Memories removal, with sources reviewed on 2026-11-13.
- **Scope:** No schema migration, public tool argument, or tool-schema digest change is included. The published `v0.38.5` tag and artifacts remain historical.

## Compatibility and limitations

Installing the package does not automatically connect every coding agent. Clients that should share one store still point at the same persistent `AGENT_MEMORY_BRIDGE_HOME`.

- The public tool-schema SHA-256 remains `24c5c52321d61b4b6f647c0d74e2d8304ca68716c403e08a274e9badfd8dc9f8`.
- There are exactly 17 tools in the public MCP interface, and the schema remains v12.
- No schema migration is required for existing v12 data.
- This release does not authorize upgrading an existing production deployment. That remains an independent operator decision.
