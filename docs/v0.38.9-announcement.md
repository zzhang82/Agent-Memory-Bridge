# Agent Memory Bridge v0.38.9 — Reviewable Offline Memory Audit, Session Index Compiler, and Windows WAL Stability

Agent Memory Bridge v0.38.9 adds a reviewable offline memory audit command (`memory audit` and `audit-memory`) for scanning durable memories against live repository checkouts and staging hidden `revise` candidates for drifted claims (#95), adds a size-capped session-start memory index compiler (`compile-index`) as a pure derived projection (#96), adds an operator-provided session log audit command (`audit-logs`) to extract review candidates with zero transcript persistence (#97), and fixes cross-platform Windows WAL checkpoint flakiness in the knowledge explorer test suite. The schema remains v12 and the public MCP surface remains exactly 17 tools. There is no automatic learning and no MCP tool #18.

## What changed since v0.38.8

- **Reviewable offline memory audit (#95):** Extends the operator review surface with `python -m agent_mem_bridge memory audit` (and `audit-memory`):
  - Compares durable memories against the bound Git repository and recorded dependencies, scanning memories that report `recheck_status == "needs_recheck"`.
  - For memories whose declared file or commit has drifted at HEAD (`depends_on_repo:changed:<path>`) or whose memory dependencies are superseded or missing, builds structured `revise` candidates.
  - In shadow / dry-run mode (default), generates an auditable report without writing to the database or modifying any state.
  - When `--stage` is supplied, stages at most a small, bounded set of candidates with `candidate_status=needs_review` into the hidden learning candidate lane.
  - Staged candidates are never visible to normal `recall` or `browse` operations and cannot auto-promote; an operator must review and confirm them before any durable revision occurs.
- **Session-start memory index compiler (#96):** Adds `compile-index` (and `memory compile-index`):
  - Compiles an operator-visible Markdown table-of-contents index of current confirmed durable records (decisions, constraints, gotchas) for session-start orientation.
  - Strictly capped at <= 200 lines and <= 25 KB to avoid prompt bloat and attention degradation.
  - Built as a pure derived projection ($Index = \pi(Durable)$) holding zero durable authority, with a documented fail-open fallback path that preserves targeted `recall`.
- **Operator-provided log audit source (#97):** Adds `audit-logs` (and `memory audit-logs`):
  - Parses operator-provided session logs (JSONL or plain text) to extract candidate gotchas and decisions with provenance references.
  - Enforces zero transcript persistence (raw messages, user prompts, and tool output are never written to durable SQLite tables).
  - Staged candidates enter the #95 review queue with `candidate_status=needs_review` and require explicit human confirmation.
- **Windows WAL checkpoint CI stability:** Ensures SQLite WAL frames are explicitly checkpointed and truncated to a steady state prior to read-only byte assertions in `test_knowledge_explorer.py`, resolving non-deterministic garbage collection and passive checkpoint timing on Windows runners.
- **Scope:** No schema migration, public tool argument, or tool-schema digest change is included. The published `v0.38.8` tag and artifacts remain historical.

## Compatibility and limitations

Installing the package does not automatically connect every coding agent. Clients that should share one store still point at the same persistent `AGENT_MEMORY_BRIDGE_HOME` or remote HTTP endpoint.

- The public tool-schema SHA-256 remains `24c5c52321d61b4b6f647c0d74e2d8304ca68716c403e08a274e9badfd8dc9f8`.
- There are exactly 17 tools in the public MCP interface, and the schema remains v12.
- No schema migration is required for existing v12 data.
- This release does not authorize upgrading an existing production deployment. That remains an independent operator decision.

## PyPI Distribution and release provenance

After this release is published, install the version-pinned package with:

```sh
pip install agent-memory-bridge==0.38.9
```

GitHub Releases remains the release source of truth, and actual PyPI and GHCR availability must be checked separately. Publishing a GitHub Release for the `v0.38.9` tag triggers the existing wheel/sdist verification workflow, PyPI Trusted Publishing through GitHub OIDC, and the container workflow that validates and publishes `ghcr.io/zzhang82/agent-memory-bridge:0.38.9`.
