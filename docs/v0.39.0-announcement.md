# Agent Memory Bridge v0.39.0 — Plain-Words Pass, Verified Client Connectors, and Per-Client Triggers

Agent Memory Bridge v0.39.0 ships a human-first plain-words pass across `README.md`, `README.zh-CN.md`, `Explore`, `Inspect`, and CLI `--help` alongside a one-page code-reader glossary (`docs/GLOSSARY.md`), adds one-command client connectors (`connect`) with a three-tier connection check and cross-client bridge proof for Claude Code, Cursor, Codex, Cline, and VS Code, and packages per-client workflow trigger reminders (`triggers` and `trigger-hook`) with an explicit 6×5 capability matrix. The schema remains v12 and the public MCP surface remains exactly 17 tools. There is no automatic learning and no MCP tool #18.

## What changed since v0.38.10

- **Plain-words pass and code-reader glossary:**
  - `README.md` and `README.zh-CN.md` present capabilities in everyday product language (Decisions and Rules, Replacing Outdated Decisions, Agent Handoffs and Claim Timeouts, Tracked Work Runs and Proof Receipts, and Connected Clients and Trigger Reminders).
  - Adds [`docs/GLOSSARY.md`](GLOSSARY.md) mapping human feature names to exact code, JSON, and MCP wire identifiers (`namespace`, `supersedes`, `signal`, `lease_seconds`, `episode`, `attestation`, `derived_repository`, `governed_durable_memory`, `needs_review`).
  - Updates `Inspect` and CLI `--help` descriptions to use everyday language while keeping JSON output schemas and the 17-tool SHA-256 digest unchanged.
- **Verified client connectors (`connect`):**
  - Adds `agent-memory-bridge connect <claude-code|cursor|codex|cline|vscode>` for safe, backup-backed configuration merging that preserves sibling MCP servers and protects existing HTTP entries unless `--force` is passed.
  - Adds a three-tier connection check (`connect <client> --check`): `tier1_config_valid` (JSON/TOML syntax, client-specific keys, absolute executable paths), `tier2_server_spawn_verified` (spawning the configured command over MCP and confirming `store` and `recall` in `tools/list`), and `tier3_host_registration_status` (`host_cli_verified` vs. `host_reload_required`).
  - Adds `connect --bridge-check --from-client <A> --to-client <B>` to run the two-client bridge acceptance test (store a decision in Client A, recall it in a fresh Client B process on the same `AGENT_MEMORY_BRIDGE_HOME`).
- **Productized per-client triggers (`triggers` and `trigger-hook`):**
  - Adds `agent-memory-bridge triggers {matrix,install,test}` and `agent-memory-bridge trigger-hook --client <client>` outside `lifecycle-hook`, preserving the core vendor-key rejection guard in `lifecycle_activation.py`.
  - Ships an explicit 30-cell (6 moments × 5 clients) capability matrix distinguishing `native_hook`, `deferred_hook`, `trust_gated_hook`, and `instruction_rule`, with SHA-256 session state filenames, fail-open file locking, a 2x tool-failure counter, stop-loop guards, and cross-platform scratch-path filtering.
- **Scope:** No schema migration, public tool argument, or tool-schema digest change is included. The published `v0.38.10` tag and artifacts remain historical.

## Compatibility and limitations

Installing the package does not automatically connect every coding agent without running `connect` or configuring the client. Clients that should share one store still point at the same persistent `AGENT_MEMORY_BRIDGE_HOME` or remote HTTP endpoint.

- The public tool-schema SHA-256 remains `24c5c52321d61b4b6f647c0d74e2d8304ca68716c403e08a274e9badfd8dc9f8`.
- There are exactly 17 tools in the public MCP interface, and the schema remains v12.
- No schema migration is required for existing v12 data.
- This release does not authorize upgrading an existing production deployment. That remains an independent operator decision.

## PyPI Distribution and release provenance

After this release is published, install the version-pinned package with:

```sh
pip install agent-memory-bridge==0.39.0
```

GitHub Releases remains the release source of truth, and actual PyPI and GHCR availability must be checked separately. Publishing a GitHub Release for the `v0.39.0` tag triggers the existing wheel/sdist verification workflow, PyPI Trusted Publishing through GitHub OIDC, and the container workflow that validates and publishes `ghcr.io/zzhang82/agent-memory-bridge:0.39.0`. A tag alone is not evidence that either artifact was published.
