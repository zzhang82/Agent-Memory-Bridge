# Agent Memory Bridge v0.39.1 — Connector, Trigger, and Operator CLI Fixes

Agent Memory Bridge v0.39.1 fixes the connector, trigger, and operator CLI issues tracked as #115, #116, and #117. The schema remains v12 and the public MCP surface remains exactly 17 tools. There is no automatic learning and no MCP tool #18.

## What changed since v0.39.0

- **#115 operator memory listing and first-run titles:**
  - `memory list` omits superseded records by default, including a predecessor that stays superseded after its successor is forgotten, and `--include-superseded` adds those predecessors with their successor ids. Remote `memory list --url` uses the same default filter. Remote `--include-superseded` is refused because a remote authority cannot add the successor annotations.
  - `first-run` titles and claim labels break on word boundaries instead of cutting a word in half.
  - The `memory list` TITLE column shows the claim text instead of the `record_type:` label.
- **#116 client connectors (`connect`) and trigger install checks:**
  - `triggers install` keeps a symlinked virtualenv Python path instead of resolving it.
  - `triggers test --scope project|user` checks the installed hook command for that scope in a subprocess and reports the checked command under `--json`. On Windows the command split keeps backslashes in the executable path.
  - `connect codex` rewrites only the AMB tables in `config.toml`. Multiline strings, quoted and spaced headers, array-of-tables headers, and an inline `agent-memory-bridge` key under `[mcp_servers]` stay valid TOML. An unchanged config writes no new backup.
  - `--force` protects a differing stdio or HTTP entry. The conflict report names `existing_entry_requires_force` and says to pass `--force`. An existing entry that differs is left untouched unless `--force` is set.
  - A failed connection check reports that the spawn probe failed instead of claiming verification.
  - `connect <client> --url <url> --token-file <path>` refuses a project-scope token write unless `--allow-project-token` is set, and dry-run previews redact the token. The token file must hold one single-line printable non-whitespace ASCII token, and that config file must stay gitignored and uncommitted.
  - `connect` writes `.mcp.json` (Claude Code project scope, or VS Code Copilot project format), `.cursor/mcp.json`, `.codex/config.toml`, `.vscode/mcp.json`, or Cline settings (`cline_mcp_settings.json`).
- **#117 session index, lifecycle wording, memory show, trigger install output, and docs:**
  - `compile-index` and `memory compile-index` omit superseded records, label claims, and state the ceilings explicitly: `--max-lines` is default 200, min 10, max 200; `--max-bytes` is default 25600, min 1024, max 25600. A request below the minimum is raised and reported. The byte ceiling is enforced by dropping body lines, and the compiler no longer indexes `body_lines[-1]` when the line budget leaves a zero cutoff.
  - `lifecycle-hook` remains the generic stdin/stdout adapter. Reminder text truncates on word boundaries, and a lifecycle result can report `needs_recheck`. `triggers install` writes per-client hook entries and instruction rules outside `lifecycle-hook`.
  - `memory show` reports supersession status (`Status: superseded`) and suppresses `Offer Revise` in `Live Repo Drift`.
  - `triggers install` prints each written path (`file=...`) and notes that new untracked project files mark the Git worktree dirty. `explore` and `inspect` report `dirty_worktree` until those files are committed or gitignored.
  - Written files are `.claude/settings.json`, `.cursor/hooks.json`, `.codex/hooks.json`, `AGENTS.md`, `.github/hooks/amb-triggers.json`, `.github/copilot-instructions.md`, `.clinerules/amb-triggers.md`, and `.cline/rules/amb-triggers.md`.
  - Onboarding, README, and integration docs match this behavior.
- **Scope:** No schema migration, public tool argument, or tool-schema digest change is included. The published `v0.39.0` tag and artifacts remain historical.

## Compatibility and limitations

Installing the package does not automatically connect every coding agent without running `connect` or configuring the client. Clients that should share one store still point at the same persistent `AGENT_MEMORY_BRIDGE_HOME` or remote HTTP endpoint.

- The public tool-schema SHA-256 remains `24c5c52321d61b4b6f647c0d74e2d8304ca68716c403e08a274e9badfd8dc9f8`.
- There are exactly 17 tools in the public MCP interface, and the schema remains v12.
- No schema migration is required for existing v12 data.
- This release does not authorize upgrading an existing production deployment. That remains an independent operator decision.

## PyPI Distribution and release provenance

Install the version-pinned package with:

```sh
pip install agent-memory-bridge==0.39.1
```

GitHub Releases remains the release source of truth, and actual PyPI and GHCR availability must be checked separately. Publishing a GitHub Release for the `v0.39.1` tag triggers the existing wheel/sdist verification workflow, PyPI Trusted Publishing through GitHub OIDC, and the container workflow that validates and publishes `ghcr.io/zzhang82/agent-memory-bridge:0.39.1`. A tag alone is not evidence that either artifact was published.
